# OpenClaw Current-Turn Input

The local binding qualifies Gateway 2026.10.7's selected native `openclaw`
runtime and the existing Phonon plugin. Required peer-context, prompt-injection
and conversation-access opt-ins remain mandatory. It does not patch installed
OpenClaw files, change personal Gateway configuration, select another runtime
or start a replacement task. Existing 2026.9.3 peer receive does not thereby
gain an unverified ordinary-input receipt.

The private capability handshake explicitly reports `native_context_v1`.
Binding an ordinary-input channel also requires that explicit mode; older peer
bindings retain their existing weaker semantics. The shared per-turn inbox owns
ordinary admission and markers separately from peer mail and durable receipts.

At a successful original-run tool-result boundary, the plugin obtains an exact
batch and reauthorizes its original sources before native context effects. The
returned carrier retains the original result, native run/session, private
projection and tool identity. Native `tool_result_persist` must subsequently
observe that exact nonsynthetic carrier before the same run's next qualified
`model_call_started` can confirm context application. Neither an offer nor a
persistence candidate alone settles insertion. This is native-context evidence,
not a provider-payload or remote model-consumption claim.

Model/session/runtime changes, malformed native metadata, compaction/reset,
source withdrawal, native termination and the owning Gateway connection fence
pending confirmations. Unknown or exhausted native headroom remains unconfirmed.
Original tasks continue without queuing an unconfirmed input into another run.
Human and tool approvals retain native policy; context adds no authority.

Controlled-provider tests use isolated native state and one task-owned local
Gateway with the owner's existing Node 24 runtime and installed SDK. Ten
lifecycle/source cases plus an actual native context-application characterization
passed. Installed ordinary insertion, pre-effect source withdrawal and
SessionEngine dispatch passed with content in the original provider continuation
and confirmation before native completion. The broader 147-case lane passed
with zero failures/skips, including actual native stop, source withdrawal,
headroom, original-run closure, old peer support and controller policies.

Native fixtures reuse one task-owned, version/build-scoped compile cache rather
than cold-compiling the installed runtime for every case. Its native process
leases retire only after actual group exit, and the cache is removed after the
test file, including failures. Startup and execution deadlines were not enlarged.
The stop fixture follows the controller's logical abort plus physical interrupt
and waits for the actual original native terminal, never the control ACK alone.

The source is local and unreleased. The original-window/source fence is
independent of separate directory-admission work. Managed-MCP cross-session
end-to-end acceptance remains unfinished.
